第一部分 · 功能

场景一：基于测试集生成规则

输入一份标注测试集，自动生成该条款的完整抽取规则（语义 BOM）+ 可粘贴的提示词。这是"从 0 到 1 产规则"的场景。

⇲ 依赖（输入）

  • 测试集（Excel/CSV）：含 doc_id / block_code / expected_value（期望抽什么）
  • LLM：api_key + model + base_url（4 个生成阶段调大模型）
  • 无需 badcase、无需历史规则（从零生成）

⇱ 预期输出

  • 语义 BOM（结构化规则，见下页）
  • 完整提示词（粘抽取平台即用）
  • 选取的代表正例（带 doc_id，可追溯）
原理：统计与大模型分工——能用程序解决的（关键词/正例选取/规则校验/组装）绝不用 LLM；LLM 只做语义推理（定义规则/画像/自检/正例理由），按阶段调温。自检发现问题自动回修一轮。

场景二：优化场景生成规则

已有规则跑出 badcase（漏抽/误抽），导入后自动判类 + 针对性优化 + diff 对比，产出改进后的新版本。这是"从 1 到更好"的场景。

1badcase 导入解析
›
2判类启发式
›
3改定义/规则LLM
›
4改召回画像LLM
›
5组装 Delta程序
›
6应用(人审)合并

⇲ 依赖（输入）

  • badcase 用例集：期望值/实际值/相似度 + 问题类型（召回失败/抽取失败）
  • 源 BOM（待优化的基线版本）
  • LLM（两阶段优化调用）

⇱ 预期输出

  • 优化后的 BOM（新版本，bom_source=optimize）
  • BOMDelta diff（红删绿增，改了啥一目了然）
  • regression_warnings（防回归告警）
  • 新提示词（重组装）
原理：badcase 分两类路由——召回失败（关键词没覆盖→改画像）/ 抽取失败（召回到了没识别→改规则）。两阶段 LLM 分别改，程序化过滤 + 人审应用防回归。

两场景对比

维度场景一：生成场景二：优化
目标从 0 到 1 产规则从 1 到更好（改规则）
输入测试集（标注期望值）badcase + 源 BOM
核心依赖测试集 + LLMbadcase + 源 BOM + LLM
节点数8 个（统计+LLM 流水线）6 个（判类+两阶段优化+应用）
产出完整 BOM + 提示词优化后 BOM + diff + 新提示词
触发新条款上线 / 重新生成跑分后发现 badcase
两场景共享 BOM 契约（同一套结构化规则产物），优化基于生成的产出迭代——形成「生成 → 跑分 → 优化 → 再跑分」的闭环。

第二部分 · 集成方案

集成边界：输入 / 输出

⇲ 输入（数据湖 → 本模块）

  • 测试集：doc_id / block_code / expected_value（Excel）
  • 合同原文（可选）：抽取跑分用
  • badcase 跑分：期望值/实际值/相似度（2 格式）
  • LLM 配置：api_key / model / base_url

⇱ 输出（本模块 → 数据湖）

  • 语义 BOM（JSON）：完整结构化规则
  • 提示词（文本）：粘抽取平台
  • BOM 版本快照：每次生成/优化一版
  • 优化 diff + 跑分评测结果
最小集成 = 文件导入导出（零侵入）：上传 Excel → 下载 BOM+提示词 → 粘湖平台。无需改湖的抽取/DQ 代码。

端到端数据流 + 接口

湖 测试集→ 模块 生成BOM+提示词→ 湖 抽取跑分↺ 湖 badcase→ 模块 优化→diff↻ 湖 用新规则重跑

REST API（松耦合，JSON）

入口方法 + 路径用途
生成环POST /api/testset/scan → POST /api/generate → GET /api/runs/{id}/result测试集 → BOM + 提示词
优化环POST /api/tuning/badcases/import → POST /api/tuning/optimize → POST /api/tuning/apply/{delta}badcase → 优化 → 新版本
BOM 产出是标准 JSON（Pydantic 契约），湖可解析消费或直接用提示词文本。独立 FastAPI 服务，docker-compose 一键起，不侵入湖。

分阶段集成路径

PHASE 1 · 立即可用

文件桥接（零侵入）

湖导出 Excel → 上传模块 → 下载 BOM+提示词 → 粘湖平台。不改湖代码，先跑通价值。
PHASE 2 · 推荐目标

API 直连

湖直接调模块 API，规则自动回流。独立部署，松耦合，自动化。
PHASE 3 · 可选

嵌入式

模块代码合入湖子目录，作为官方规则引擎子模块，共用 DB/鉴权。
给数据湖的核心价值：补一个「规则编译 + 评测」引擎——让抽取规则有单一事实源（可版本/审计/对比）+ 持续优化闭环（badcase 驱动），与 Extraction / DQ 解耦。
